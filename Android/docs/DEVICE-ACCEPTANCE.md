# Android 1.2.0 真机验收

当前状态：**项目所有者于 2026-10-31 确认实体手机／平板全部测试通过，并明确授权公开正式 APK。** 这是用户报告，不是审查者亲自执行；设备型号、Android 版本和逐项截图未提供，不补造设备覆盖。自动化、编译、签名与 ZIP 校验由审查者独立复核，见 [发布审查记录](REVIEW-v1.2.0.md)。

以下保留完整验收要求，用于后续版本；不能因本次用户确认而将未提供的详细证据填写为审查者实测。

仅使用用户提供并授权 USB 调试的实体设备；不使用模拟器或 PD。不卸载应用、不清除数据、不使用 `pm clear`，不改变设备全局分辨率。截图必须避开用户真实学习记录与通知。需要连接时先通过 `adb devices -l` 只读确认设备及授权状态。

## 必须记录

每台设备分别记录：角色（手机／平板）、型号、Android 版本与 API、实际窗口宽度／字体比例、APK SHA-256、证书 SHA-256、源码提交、日期、执行者、各项结果及证据位置。不记录设备序列号、个人学习内容或密码。填写后实际记录保存在忽略的 `Android/verification/`，发布时提供不含个人信息的验收摘要。

## 界面与状态

- 竖屏、横屏：列表、详情、检测、学习记录和设置没有偏移、遮挡、裁切；长英文可换行。
- 真实分屏缩放跨越 600／840 dp：底部导航／导航栏、单栏／双栏切换正确；搜索、筛选、词条、题目、选项顺序和已答状态不重置。
- 检查 599／600／839／840 dp 临界值的自动化测试，同时记录真机可用的实际窗口尺寸；不把未到达的精确宽度宣称为真机覆盖。
- 系统字体 200% 仍可滚动和完成操作；所有交互目标至少 48 dp。
- 系统栏、挖孔、手势导航、软键盘不覆盖操作；返回键先离开设置／详情，检测离开需确认，不能意外丢题。
- 后台再返回、旋转、系统重建后保留当前题目及选项；重复点击／失败重试不会重复记录答题。

## 学习与离线发音

- 核对 326 条／130 重点、五科目、搜索及重点／收藏／错题组合筛选。
- 三种方向、五种范围、10／20／50／全部，排除已掌握后的实际题数。
- 收藏、错题、连续答对两次移出错题、三次掌握及统计保持桌面契约；结束再启动记录存在。
- 飞行模式：两种口音、三档语速、每个科目的完整词条发音均可用。
- 长按选中 `unbounded`，拖成 `unbounded function`，手动“朗读所选”；选择不会自动播放，原生复制仍可用。
- 首尾标点、纯空白和未收录片段提示正确；切换词条、离开反馈及进入后台停止旧播放，不联网或回退 TTS。
- 在独立测试存储中模拟写入失败／损坏数据，明确报错且不覆盖旧数据；不要为此修改用户真实记录或填满设备磁盘。

## 安全更新与覆盖安装

- 启动不联网，只有手动检查才查询正式版；Release 暂无 Android 附件时显示暂无对应安装包，绝不下载桌面 ZIP。
- 下载进度、断网、取消、失败重试、SHA 不符、大小不符均不能报告成功。
- 错包名、错证书、降级 code、Release／APK 版本不符、损坏 APK 被拒绝；记录纯策略测试与真实系统测试的区别。
- “允许安装未知应用”拒绝、系统安装取消、PackageInstaller 失败均不能显示已安装；不关闭 Play Protect 或其他安全防护。
- 同签名覆盖更新保留记录。只在没有该包的授权测试设备上，先安装受控的较低 versionCode 测试基线，再覆盖最终版。若设备已有更高／相同 code，不降级、不卸载、不清空；改用另一台授权实体测试设备。
- 测试基线／错误证书等夹具只保存在私有验收目录，不上传 Release，不作为正式 APK 交付。

## 发布闸门

只有手机、平板均通过，正式 APK 校验通过，签名恢复材料已妥善备份，源码提交和构建一致，才可以创建 `android-v1.2.0` 标签并向现有 v1.2.0 Release 新增 Android 附件。任何一项缺失都保留待验收构建，发布说明不得写“已验证”。桌面三个附件及原标签不变。
