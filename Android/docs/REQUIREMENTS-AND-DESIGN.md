# Android 需求、设计与发布规范

基线：Android 1.2.0，2026-10-31。后续 Android 功能由项目所有者自行开发；本文件用于需求交接、实现评审和发布验收，不授权自动修改代码。下述要求是目标合同，不等同于全部已由自动化或审查者真机验证；实际证据见 [1.2.0 审查记录](REVIEW-v1.2.0.md)。

## 1. 产品边界与优先级

- 面向数学专业面试：查词、记忆英文、理解概念、主动回忆检测与听读练习。
- 原生 Kotlin + Jetpack Compose + Material 3 Adaptive；不能用网页套壳替代原生选词、系统返回与安装交互。
- 与 macOS、Windows 保持词库、重点、学习规则、检测配置、口音、语速、数据字段和功能层级一致；允许原生平台字体、菜单和导航形态不同，不承诺逐像素复刻桌面。
- 不增加账号、跨端同步、广告、分析 SDK、远程学习数据库；不要求首次联网下载音源。学习与发音始终离线，联网仅限用户主动检查／下载更新及打开发布页。
- 本轮只通过 GitHub 发布通用正式签名 APK，不上架应用商店，不发布调试 APK 或测试夹具，不使用模拟器或 PD。
- 严重等级：P0 为关键安全／大面积不可恢复数据问题；P1 为主要流程不可用、稳定崩溃或严重数据错误；P2 为有条件触发、可恢复的可靠性／交互问题。P0/P1 必须阻断发布；P2 需记录影响、规避办法和处理决定，不能因测试通过而隐去。

## 2. 身份、兼容性与构建合同

| 项目 | 固定要求 |
| --- | --- |
| 名称 | 数学面试词汇 |
| applicationId | `com.xingyiyao.mathinterviewvocab`，后续更新不得改变 |
| Android 1.2.0 | `versionName=1.2.0`，`versionCode=1` |
| 最低 / 编译 / 目标 API | 29 / 36 / 36 |
| 发布形态 | 单个 Universal Release APK，正式长期证书签名、非 debuggable |
| 工具链基线 | JDK 17、Gradle Wrapper 8.13、AGP 8.13.2、Kotlin 2.3.20 |

版本码必须严格递增；后续修复版不能用同一 versionCode 冒充升级。代码版本、APK 版本、附件名和 Release 版本必须一致。依赖更新另行评估，不以“有更新”提示为由直接升级整套依赖。

JDK、SDK、Gradle 缓存和生成目录使用项目独立路径，不修改全局 Java。SDK 许可由使用者亲自确认。Wrapper 固定分发地址与 SHA-256；提交解析后的依赖锁，不提交 SDK、模型、依赖缓存或构建输出。

## 3. 信息架构与设计原则

主导航只有“词汇／检测／学习记录”三项，设置从顶部进入。导航、词汇索引和阅读区职责分离，不嵌套多套竞争的侧栏。设置与统计分离，学习记录页不堆放发音和更新控制。

布局依据实际应用窗口宽度；不是设备型号、物理分辨率或“是否平板”开关。旋转、分屏和窗口缩放均重新判断。

| 宽度 | 主导航 | 词汇结构 |
| --- | --- | --- |
| < 600 dp | 底部导航 | 列表与详情分别显示；详情返回列表 |
| 600–839 dp | 左导航栏 | 列表／详情单页，阅读列居中 |
| ≥ 840 dp | 左导航栏 | 约 320 dp 词汇索引 + 剩余宽度详情 |

详情、检测与学习记录阅读列最大 820 dp；设置最大 560 dp。列内卡片填满可用阅读宽度，不能出现首卡异常变窄或固定宽度溢出。边距随可用空间收敛，不能靠横向滚动掩盖文字／按钮裁切。

视觉保留浅色学术纸张主题：墨蓝 `#14213D`、公式蓝 `#2E5AAC`、纸白 `#F7F9FC`、浅线 `#D9E4F2`；成功绿 `#1C7C54`、错误红 `#B54343`。中文标题使用系统衬线，英文与正文使用系统无衬线，统计数字可用等宽字体；不捆绑 Apple 字体或 SF Symbols。

当前设计参考：卡片圆角 18 dp、卡内留白约 22 dp、页面边距约 20–24 dp；这些是可调整设计参数，不凌驾于大字体和小窗口可用性。重点加粗用于词汇本体，不把所有说明都做成粗体。

## 4. 自适应、无障碍与系统行为

- 所有可点击目标至少 48 dp；用文字、图标／状态标签补充颜色，不仅靠红绿区分答案。
- 系统字体 200% 时，长术语、IPA、按钮及菜单可换行或滚动；仍可完成查词、选择答案、下一题、返回和设置。
- 导航栏标签与项高应适配大字体；列表过滤区不能把词表挤成零高度。横屏、软键盘出现后，控件仍可达。
- 尊重系统栏、挖孔、手势区和 IME Insets，避免重复应用 Insets 导致二次偏移；不锁定方向，不用全局修改设备分辨率完成验收。
- 系统返回：先关闭菜单／确认框，设置返回原模块，单栏详情返回列表；进行中的检测退出／替换必须确认。切模块允许保留未完成检测。
- 切换布局不得重置搜索、筛选、所选词条、当前题号、已选答案、选项顺序及保存状态。
- 旋转及系统进程重建使用 ViewModel／SavedState 恢复轻量编号状态；不把整份词库、所有长文本和重复选项塞入 Bundle。
- 已成功保存的答题永久记录必须独立于临时页面状态；用户结束应用后仍保留。未完成检测是否跨主动强制停止恢复，应明确说明，不能混同于已答记录。
- 新词条／新题目应从题干或顶部开始；同一内容仅因旋转、分屏重排时尽量保留阅读位置。把内容身份变化与窗口变化区分开。

## 5. 规范内容与词汇页

唯一词库为仓库 `Resources/terms.json`；Android 构建从规范资源生成 assets，不维护另一份可漂移的词库。

| 科目 | subjectID | 数量 |
| --- | --- | ---: |
| 常用数学学科名称 | `subjects` | 11 |
| 数学分析 | `analysis` | 163 |
| 高等代数 | `algebra` | 110 |
| 概率论 | `probability` | 27 |
| 数理统计 | `statistics` | 15 |
| 总计 | 稳定 ID 1–326 | 326（其中重点 130） |

每条保留 `id`、科目中英文、`chinese`、`english`、`definition`、`important`、`speechText`、美式／英式 IPA。更新不得因排序变化而重编号，不能把旧收藏或错题指向其他术语。数学符号正常显示，不把原始 LaTeX 控制符当普通英文朗读。

词汇页支持中英文及释义搜索，搜索忽略大小写；科目与重点／收藏／错题可以组合筛选。显示实际结果数和总数，空结果提供清除条件入口。切换搜索／筛选后若旧选中词已不可见，应清空详情或明确提示，不能保留误导性的高亮。

详情展示中文、科目、蓝色可选英文、两种 IPA、概念释义、收藏与学习状态。收藏是独立维度；“已收藏”不能替换“已掌握／待复习”。重点在列表、详情和检测中一致加粗。

## 6. 检测功能与学习规则

检测方向为中译英、英译中、双向混合。五种范围为重点、全部、指定科目、错题、收藏；题量为 10／20／50／全部，不把词库总数硬编码为“全部”。排除已掌握时，各范围的可出题数和实际题量应同步扣除。

每题四个不同词条编号的选项，正确选项只出现一次；尽量排除显示标签相同的干扰项。混合方向与选项顺序只在生成题目时随机，不能因重组／旋转再次洗牌。固定随机种子用例应能与桌面规则对照。

选择后立即显示反馈并保存一次答题。保存成功才允许下一题；失败保留原题、所选答案与同一 attempt UUID，提供重试，不能重复计分。反馈可朗读和选词，选项本身不提供选词朗读，以免选项交互冲突。

规则保持一致：答错加入错题并清零连续正确次数、移除掌握；连续答对两次移出错题、三次标记掌握。收藏不随上述状态变化而改变。检测结束只汇总本次 attempt UUID，不能把历史其他检测混入结果。

检测偏好需保存 `direction`、`scope`、`questionLength`、`selectedSubjectID`、`includeMastered`。旧数据缺字段按明确默认值读取；未知／非法枚举不能进入导致崩溃的状态。默认值与当前桌面契约保持一致。

## 7. 离线语音与选词交互

复用 `Windows/resources/audio-manifest.json` 与同目录 `audio/` 的 2328 段 Kokoro 预生成 MP3。美式 `en-US` / `af_heart` 与英式 `en-GB` / `bf_emma` 是不同音源，不能复制改标签冒充口音；不含 Google 翻译音频或模型。

运行时不加载 Kokoro 模型，不联网补音，不回退系统 TTS。完整词条使用 `speechText`；所选内容按索引查找。三档语速 0.75×／1×／1.25×，不通过更换音源冒充变速。默认口音、语速可持久保存；试听也必须取规范词库文本，不能因大小写与索引不一致而缺音。

原生英文文本支持长按、拖动选择，保留系统复制；增加“朗读所选”菜单及明确按钮。仅改变选区绝不自动播放；无有效选区按钮禁用。选择完整单词、多词、带内部连字符／撇号的片段可用；纯空白／纯标点不播放。

UTF-16 选区必须验证边界，防半截代理对。清理边缘 Unicode 空格和标点，保留内部标点；音频规范化按现有契约执行 NFKC、撇号／连字符统一、内部 Unicode 空白折叠，并保留大小写。文件键为 SHA-256(UTF-8 `accent + "\n" + normalizedText`)，文件名为键加 `.mp3`。

离线索引覆盖完整词条、完整单词及收录的连续完整词组选区；不承诺任意字母片段。缺失时明确提示并建议选择完整单词或完整词条，不能静默播放相近片段。切词条清选区，新发音停止旧发音，离开详情／反馈或进入后台停止播放；旋转不得创建多个播放器叠音。

构建检查覆盖标记完整、缺失数 0、失败列表空，并逐项验证文件名、数量、字节数与 SHA-256。APK 中实际资源再独立验证，不能只检查源码文件夹。项目 MIT、Kokoro Apache-2.0、音源来源与 Android 第三方声明须随包提供。

## 8. 数据安全与持久化

学习记录、发音设置存应用私有目录的 `progress.json`、`settings.json`，不申请公共存储权限。字段沿用桌面：attempts、favoriteIDs、correctStreak、wrongIDs、masteredIDs、quizPreferences。选项记录保存稳定词条 ID，不保存临时 A/B/C/D 位置。

使用串行化／Mutex 与原子文件替换；磁盘写入成功并确认后才发布新的 UI 状态。损坏、权限、磁盘不足、目录创建／重命名失败必须报错，不自动写默认值覆盖原记录。两份文件独立读取；其中一份损坏不能无声丢掉另一份有效数据。

恢复损坏文件是用户明确操作：先唯一命名备份原文件，再重置选定的数据；备份失败则停止重置。普通重置须确认，并保留发音设置和检测偏好。错误提示不得声称失败操作已保存。

相同包名与证书正常覆盖更新保留数据；不通过卸载、`pm clear`、删除私有目录或降级来完成验收。关闭云备份与设备迁移备份，不把学习数据打入 APK、Git 历史、日志或公开截图。

## 9. 手动更新协议与安装状态机

只在设置中手动检查本仓库最新正式 Release；拒绝 draft、prerelease、非法版本号与降级。Android 附件必须精确为 `MathInterviewVocab-Android-universal-v版本.apk`，校验文件为 `SHA256SUMS-Android.txt`。新版本缺少任一 Android 附件时提示暂无对应安装包，不能下载桌面文件。当前版本已是最新时不要求重下同版 APK。

网络限定官方 HTTPS 地址，验证每一跳的主机、端口和重定向次数；不带 Cookie、认证凭据或学习文本。对元数据、校验文件及 APK 都限制大小，超时、断网、HTTP 错误、压缩编码异常等可恢复报错。

下载流计算 SHA-256，严格核对声明大小及校验文件；API 提供摘要时交叉核对。验证真实 APK 包名、签名证书集合、Release 版本、较高 versionCode；解析失败关闭安装入口。安装前再校验，并在复制到 PackageInstaller Session 时再次验证流的大小／摘要，防止校验后内容变化。

建议明确区分：空闲、检查、可用、下载、验证、就绪、安装准备、等待来源授权、等待用户确认、系统安装、成功／失败。不能用一个安装布尔值混同“后台校验尚未建 Session”和“系统 Session 已结束”。

每个操作有唯一代次或令牌；取消后旧任务不得修改新任务状态、清空新 Release 或删除新下载。取消只清理本次拥有的私有临时目录，不能误删学习数据或其他下载；支持再次检查／重试。

安装必须由用户点击。缺来源权限时打开系统授权设置，拒绝后保持可解释的状态；有权限后仍需 PackageInstaller 用户确认。回调校验所属 Session、唯一随机标记和结果，不能将“Session 不存在”“已提交”“返回前台”当安装成功。

后台／前台、授权页面往返、进程重建与系统确认延迟都需覆盖。只取消本应用明确拥有的失效 Session，不取消仍在准备的当前操作，不后台自动弹安装页面。错误包、错误证书、损坏包、取消和拒绝不能误报成功；不要求关闭系统安全防护。

## 10. 签名、源码与 GitHub 发布

长期保留同一正式签名密钥。私钥、密码、签名配置和恢复材料在仓库外、非同步、受权限保护的专用位置，发布前验证备份能恢复同一公开证书；公开只保留证书指纹。另存受控离线介质是额外推荐，不能把同盘双份复制宣传成可防整机故障的备份。

源码提交须明确清单：Android 工程／Wrapper／锁文件、测试、规范内容、许可证与文档；不包含成品、SDK、缓存、截图、日志、个人路径配置、用户记录或秘密。Android 构建复用现有词库／音频，不上传重复资源目录。

Android 首发在既有 v1.2.0 Release **仅新增** APK 与 Android 独立校验文件；原 Mac／Windows ZIP、原 `SHA256SUMS.txt`、原 v1.2.0 标签及其指向保持不变。不能为 Android 替换或重新构建桌面成品。

另建 `android-v1.2.0` 源码标签，明确指向实际构建输入对应提交；这是源码标签，不再创建一个混淆更新协议的独立正式 Release。发布说明链接该标签，指出原 v1.2.0 自动源码归档仍为当时桌面源码。

先完成本地与真机验收、固定源码，再上传；上传失败不写发布成功，不覆盖同名已有附件而不检查来源。发布后用公开链接实际下载两个 Android 附件并核对 SHA-256、大小及内容；同时复查三个原桌面附件的 ID、大小与摘要都未变化。

## 11. 验收矩阵与证据等级

自动化至少覆盖：词库契约／筛选／随机出题、学习状态转换、旧格式兼容、存储故障与并发保存、UTF-16 选区、全部音频、更新解析／流校验／取消／身份验证；Debug、Release 都执行，Lint 无阻断错误。

界面覆盖手机、平板、599／600／839／840 dp、长文本、200% 系统字体、横竖屏、分屏与软键盘。纯断点函数通过不等于真实 Adaptive 壳层通过；局部 Compose Density 测试不等于原生 TextView 跟随系统字体正确。

实体手机和平板分别验证：返回导航、旋转／重建后的当前题目与选项、飞行模式两口音三语速与长按选词、正常记录保存、覆盖更新保留数据、安装拒绝／取消／失败。新增回归重点：下载取消后立即重试、安装准备时快速切后台返回、换题后滚动位置。

同签名升级测试使用明确授权的测试基线与较低 versionCode；不能卸载／清空已有数据，也不能把错误证书等测试夹具公开。记录型号、系统版本、APK 哈希、测试项目、执行者及结果；不记录设备序列号或个人内容。

报告区分“自动化实测”“审查者真机实测”“用户报告”“静态推断”和“未验证”。用户确认测试通过时可以注明来源；没有提供的设备型号、系统版本及截图不得补造。发现 P0/P1、资源／签名不一致、真机失败或用户未批准发布时，停止正式发布。
